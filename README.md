# NekoDock · 猫坞

自托管的多实例 AI 聊天机器人控制台。

通过 Web 控制台管理多个 QQ Bot。每个实例绑定一个群聊或私聊，使用独立 Worker 容器、SQLite 数据库、Pi 会话和工作目录。NapCat 负责 QQ 登录与收发，桥接层负责调度和发送，Pi SDK 负责模型调用与工具执行。

## 部署控制台

需要 Docker Engine 和 Docker Compose。首次部署：

```bash
cp compose.console.yaml.example compose.console.yaml
docker compose -f compose.console.yaml --profile build build worker-image
docker compose -f compose.console.yaml build console
docker compose -f compose.console.yaml build plugin-runner
docker compose -f compose.console.yaml up -d console plugin-runner
```

打开 [http://127.0.0.1:4180/](http://127.0.0.1:4180/)，设置管理员密码，添加 NapCat 连接，再创建实例、选择连接、填写模型和人格配置并启动。控制台端口默认只绑定宿主机回环地址；远程访问可使用 SSH 转发。

`compose.console.yaml.example` 是部署样板，实际 `compose.console.yaml` 不纳入版本管理。共享 Worker 镜像为 `nekodock-worker:latest`，控制台镜像为 `nekodock-console:latest`；`worker-image` 仅用于构建，实际 Bot 容器由控制台创建。共享 `plugin-runner` 处理平台解析和视频下载，凭据由 Console 自动生成，使用独立的引导卷传递；不需要手工配置实例 env。每个实例的数据卷独立，只有控制台挂载 Docker Socket，Worker 和插件运行器均不挂载。

受管实例的设置统一保存在控制台数据库。无需为每个 Bot 创建 env、Compose 或人格文件。群聊／私聊类型及目标号码创建后不可修改，更换绑定时创建新实例。复制实例只复制配置，新实例从空会话开始。

### NapCat 连接

在 NapCat 中启用**正向 WebSocket 服务端**，设置监听端口与访问 Token。Console 主动连接它，每个连接资源只建立一条上游 WebSocket；Worker 经 Console 接收目标消息和提交回复。Web 的“NapCat 连接”页面集中管理地址、加密 Token、重连参数和在线状态。

| 部署位置 | NapCat 连接中填写的示例地址 |
| --- | --- |
| NapCat 与 Console 同一 Docker 网络 | `ws://napcat:3002` |
| NapCat 或转发端口在 Docker 宿主机 | `ws://host.docker.internal:3002` |
| NapCat 在其他可达服务器 | `wss://napcat.example.com` 或对应 `ws://` 地址 |

`127.0.0.1` 在容器内指向容器自己。访问宿主机服务应使用 `host.docker.internal`；样板和动态 Worker 配置包含 `host-gateway` 映射，无需切换为 host 网络。宿主机端口还需满足 Docker 到该监听地址的可达性。地址使用根路径，Token 单独填写，不放进 URL。

Console 按连接资源、群聊／私聊类型和目标号码，将全部匹配消息分发到相应 Worker，不广播无关会话。Worker 保留忙碌判断、回复策略、指令和模型调度。控制台禁止同一连接或同一登录 QQ 的同一目标同时运行多个实例。不同实例对 QQ 用户显示为对应 NapCat 登录的账号。

连接资源可供多个实例引用；修改时界面显示受影响实例，被引用的连接不能删除。Worker 不持有 NapCat Token，也不能指定任意发送对象。每套独立 Console 各自维护连接池，跨服务器部署的两个 Console 不共享上游连接。

Console 与 Worker 之间通过 SSE 实时投递、HTTP 确认落库和提交发送。短暂断线、重启期间的入站事件保存在有界的短期投递队列，Worker 入库确认后清理；手动停止实例不继续接收新消息。重新连接补投未确认事件，Worker 按消息 ID 去重。投递缓存不加入模型上下文；NapCat 断线期间未收到的消息无法补回。

单条入站事件最多 16 MiB，每实例待投队列最多 1000 条、32 MiB、保留 24 小时；超限或过期通过日志和队列计数记录。单张图片及单条语音最大为 16 MiB，默认仍为 10 MiB 和 5 MiB。插件视频使用独立流式资产通道和视频限制，不占图片／语音的 JSON 媒体限额。

升级旧控制台时会自动将现有实例的地址和 Token 归并为共享连接，保留实例卷、配置版本、Pi 会话和工作目录。升级前备份控制台数据库与主密钥，先排空并停止该控制台管理的旧 Worker，再更新 Console 和共享 Worker 镜像、启动原实例，避免两种接收方式同时工作。

## 实例配置

配置按版本保存，界面分别显示已保存和已生效的版本。运行中的配置修改等待当前轮生成与已受理发送结束后应用。供应商密钥加密保存，读取配置时只返回是否已设置，不回传密钥正文。

### 模型服务

每个实例显式配置 Base URL、模型 ID、API Key 和 API 协议。没有隐式的默认账号或供应商；支持不需要密钥的本地服务。

| 配置 | 说明 |
| --- | --- |
| API 协议 | `Responses` 或 `Chat Completions`，对应 `openai-responses` / `openai-completions` |
| Base URL | HTTP(S) 基础地址，通常包含 `/v1`，不包含 `/responses` 或 `/chat/completions` |
| 模型 ID | 按供应商要求填写完整名称；样板中的 `your-model-id` 需替换为实际模型 ID |
| 思考等级 | 英文 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`；必须符合模型及协议实际支持 |
| 最大输出 Token | 默认 `8192`，与 QQ 文本分段上限分开 |

图片输入、思考参数分别通过模型能力开关声明。关闭思考参数后保留界面中的等级选择，但不发送该参数。配置不能赋予上游模型原本不支持的能力；错误请求不会自动切换协议或重新执行整批消息。

### 人格与基础指令

人格直接在 Web 的“人格设定”中编辑，作为本实例的身份、性格、称呼和语言风格。Worker 直接把人格传给 Pi SDK，不生成或挂载 `AGENTS.md`，也不读取 Pi 的用户配置、扩展和工作目录人格文件。

[prompts/base-instructions.md](prompts/base-instructions.md) 提供英文基础指令，包含日常聊天、消息身份与引用、回复目标、任务执行、工具使用和容器环境说明。每轮以当前基础指令和该实例人格构成有效 system prompt；用户输入提交按接收顺序排列的新增消息及本轮应答目标 ID。

日常交流优先回应眼前的话题，按时间、话题连续性和明确引用使用历史，不强行关联旧闲聊。长任务只在实质结果、重要阻碍、需要对方决定或完成时发送中途回复。面对同一阻碍，最多进行三次有依据的尝试，随后如实说明问题和未完成部分。

### 文件与终端权限

| 开关 | 实际权限 |
| --- | --- |
| 允许写入文件 | 注册 `edit` / `write` 工具；文件工具限制在当前工作目录内，检查路径与符号链接 |
| 允许终端命令 | 注册 `bash` 工具；以容器内 `node` 用户权限运行命令 |

读取工具 `read` 始终可用，也能读取支持格式的本地图片。终端命令的工作目录不是沙箱，启用后可访问 `node` 用户有权访问的容器文件。文件写入开关限制文件工具，不会限制已授权 Bash 命令的写入能力。每个实例继续通过独立非 root 容器和独立数据卷隔离。

管理凭据和供应商密钥不会传入 Bash 环境。开启“命令与脚本继承代理”时，代理认证信息会作为代理环境变量提供给这些程序。Pi 配置由 Worker 显式装配，不要求维护 `models.json`、`settings.json` 或 MCP 服务配置。

### 网络代理

在每个实例的“网络代理”页设置开关、HTTP(S) 代理地址、可选用户名与密码、绕过列表，以及命令与脚本是否继承代理。配置和凭据沿用控制台数据库的版本管理与加密存储；旧实例默认关闭。地址只填写协议、主机和端口，不放凭据或路径。首版不接受 SOCKS、PAC 和透明代理配置；HTTP 代理也可以通过 CONNECT 访问 HTTPS 服务。

| 请求 | 代理行为 |
| --- | --- |
| 模型生成、自动／手动压缩、自然语言定时任务 | 使用该实例代理，遵守绕过列表 |
| Tavily 搜索与提取、MiMo、Edge TTS、远程收发图片下载 | 使用相同实例策略；Edge 的 WSS 显式选择代理 |
| Bash、Python／Node 定时脚本 | 开启继承后提供代理环境，第三方库仍需支持或显式使用它 |
| Worker 与 Console 的心跳、消息 SSE、发送、日志和任务同步 | 始终使用独立直连客户端 |
| Console 与 NapCat | 不受实例代理影响 |

默认绕过 `localhost`、`127.0.0.1`、`::1`、`host.docker.internal`。列表支持逗号、空白或换行分隔；主机与域名匹配本域及其子域，可使用 `.example.com`、`*.example.com`，可指定端口，如 `api.example.com:8443` 或 `[::1]:8080`。IP 支持精确匹配及 IPv4／IPv6 CIDR，如 `10.20.0.0/16`、`2001:db8::/32`；CIDR 不附加端口，只匹配 URL 中的 IP，不通过 DNS 判断域名所属网段。`*` 绕过所有请求。内置请求和 Edge 使用统一判断；脚本库的 `NO_PROXY` 和浏览器的 bypass 支持范围不同，不能保证 CIDR 或端口限定规则一致，需要兼容时同时列出实际 IP。

容器访问宿主机代理可填写 `http://host.docker.internal:7890`，但宿主端口必须监听在容器可访问的接口。容器中的 `127.0.0.1` 指向容器自身。配置选中代理后，连接或认证失败不会自动直连重试；当前轮及发送 ACK 收尾后切换新版本，停止中的实例下次启动应用。

“检测当前生效配置”由运行中的 Worker 请求模型 Base URL 下的 `/models`，不发送模型 API Key，不生成回复，不发送聊天消息。结果标明被测版本、代理／直连路径、HTTP 状态和耗时；401、403 或 404 仅表示已经收到目标响应，不能说明模型可用或长流式请求稳定。停止中的实例不会为检测自动启动。检测记录短期保存在控制台内存，不写入会话或任务历史。

工具环境同时提供大小写的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`WS_PROXY`、`WSS_PROXY`、`NO_PROXY`，Node 启用 `NODE_USE_ENV_PROXY`。Playwright 需在启动浏览器或创建 context 时显式传入辅助配置：

```js
const proxy = JSON.parse(process.env.NEKODOCK_PLAYWRIGHT_PROXY ?? 'null') ?? undefined;
const browser = await chromium.launch({ proxy });
```

Python 可使用 `json.loads(os.environ.get('NEKODOCK_PLAYWRIGHT_PROXY', 'null'))`。不要把配置对象或代理环境打印到工具输出或写入脚本源码；关闭代理或关闭工具继承时，这些环境变量不会从宿主环境继续继承。代理属于应用网络配置，不是限制任意用户程序网络访问的防火墙。

## 消息与回复

每个实例只有一个串行执行循环，WebSocket 接收不被模型执行阻塞：

```text
Console 路由 → Worker 消息落库 → 决定批次和是否允许回复 → Agent 执行
                                ↓
             send_message 受理 → 持久化 → Console 转交 NapCat
                                ↓
             Agent 结束 + 发送收尾 → 推进处理位置 → 下一批
```

群聊中，被 @ 时回复；其他非表情包消息可选择按概率触发或由 Jev 判断。私聊正常回复。普通未触发消息作为背景保存，随下一次触发提交；积压超过批次上限时，可以先追加背景上下文，不调用模型生成。

实例「基本设置」中的「普通群聊回复策略」默认是概率回复；选择「Jev 判断」后，单独配置 Base URL、Model、API Key、判断阈值、超时和可选补充说明。Base URL 包含 API 根路径，例如 `https://api.typesafe.ai/v1`，程序追加 `/systemone`，支持自定义路径前缀。判断服务与主聊天模型独立，使用实例的网络代理；API Key 加密保存，管理接口和日志均脱敏。保存后的配置按实例配置版本更新流程生效。

Jev 使用原生 System One 的 `noul` 答案判断每条候选消息，分值达到阈值才触发，默认阈值 `0.7`，不再进行随机抽样。仅空闲时的普通群聊消息参与判断；私聊、直接 @ 和内置指令仍走原有流程。判断输入是有界的近期文本和真实外层候选消息，不包含主会话完整人格、工具记录、长期记忆或图片 Base64；已有分享增强可作参考，不等待媒体处理。判断提示、分值和错误不进入 Pi 主会话或长期记忆。超时、错误或非法响应时本次不主动回复，不自动回退到概率模式，不发送群内报错，详情见实例日志。

处理期间收到的普通群消息只保存，不抽样、不调用 Jev、不提示，即使回复概率为 100% 也相同。此时被 @ 会立即回复“我正在想上面的消息怎么回，你等会哦”，问题排入后续批次；等待提示不进模型上下文，也不转成语音。

### `send_message`

所有 QQ 回复通过 Pi 自定义工具 `send_message` 发送，参数是有序的 `messages` 数组：

```json
{
  "messages": [
    {"type": "text", "text": "这是生成的图片。"},
    {"type": "image", "path": "/data/workspace/output/chart.png"}
  ]
}
```

一次调用可发送多条消息，一轮也可在重要节点多次调用。目标群或私聊由实例固定，工具不能指定其他接收对象。普通聊天中，工具先保存请求和分段并启动发送，再等待本次请求的投递结果，最多 5 秒；返回 `accepted:true`、每条逻辑消息的 `messageRef`、投递状态和分片计数。`sent` 表示所有分片已收到 NapCat 成功 ACK，不表示对方已读；`pending` 表示仍在处理，等待超时不会取消发送或触发重发。处理结束后，按实际结果返回 `failed`、`unconfirmed`、`partial` 或 `cancelled`，并附已知的错误码。已受理请求的投递失败不等于入队失败，不应重复提交整条消息。

后续 ACK 更新账本和控制台，不额外触发模型生成。最终答复受理后模型应结束本轮，待发消息由 Worker 继续收尾。定时任务沿用异步受理回执；仅有 `accepted:true` 时同样不能据此认定已经送达或重复发送。

文字与文字／艾特组合消息可以分别设置 `replyTo`，值为上下文提供的真实 QQ `messageId`。一次调用中的不同回复可引用不同消息；长回复仅首个分段携带引用，带引用的回复保持文字发送。图片暂不接受引用参数。Console 按连接、登录账号、实例和聊天目标校验消息归属，并在实际发送前拒绝引用已撤回消息；未登记的旧消息 ID 不能作为引用目标。

模型可用 `recall_message({"messageRef":"发送工具返回的引用"})` 取消待发或撤回自己发送的逻辑回复。实际 QQ 分段逐条记录结果，部分成功或结果不明不会显示为全部撤回。用户、管理员及机器人自己的撤回都以真实事件同步到聊天历史；界面在原位置标记撤回，并保留展开原内容的入口。

撤回保留原始消息、附件及工具调用，在模型上下文追加状态事件，不因原消息是否已提交而删除原文，也不单独触发模型回复。后续历史检索和记忆整理携带最新撤回状态；撤回本身不等同于忘记、删除长期记忆或回滚已经执行的任务。

Pi 的最终 assistant 文本只用于结束执行，不自动发送到 QQ，也没有固定的 JSON 收尾协议。执行完成由 SDK 生命周期判断，再由父 Worker 完成已接受消息的发送收尾。发送工具不可用或结果中断时，不要求模型查询状态或补发。

群聊支持在同一条消息中混合艾特和文字：

```json
{
  "messages": [
    {"type": "message", "segments": [
      {"type": "at", "userId": "2001"},
      {"type": "text", "text": " 这是问题一的回答。"}
    ]},
    {"type": "message", "segments": [
      {"type": "at", "userId": "2002"},
      {"type": "text", "text": " 这是问题二的回答。"}
    ]}
  ]
}
```

`at.userId` 来自消息的 `senderId` 或对话中明确给出的 QQ 号，转换为 OneBot 原生 `at` 段。纯文本 `@昵称` 不产生艾特。多个用户的问题可在同一轮分别回复；私聊不提供群聊艾特类型。长文字按 Unicode 码点拆分，艾特保持完整和相对顺序。

### 停止当前回复

实例「当前会话」页提供「停止当前回复」，可中止本轮普通对话的准备、模型生成和后续工具调用；Pi 子进程不响应取消时，在 1 秒宽限期后终止其进程组。实例继续运行，保留原会话、历史及已经完成的工具操作，新触发消息按原策略继续处理。旧版 Worker 需更新后才能使用。

停止指令绑定本轮 `runId`，独立控制连接断开后可重放，重复点击不会影响下一轮。未发出的回复及后续分段被取消；已经交给 NapCat 的单条发送继续确认回执，仍可能到达 QQ，已发送内容不自动撤回。界面区分“停止请求已接受”“正在停止”和“停止尚未确认”，收尾后记录“已由管理员停止本轮回复”，不向 QQ 发送模型故障提示，也不重放被取消的批次。

「停止实例」仍等待当前工作收尾；等待期间也可停止当前回复。本按钮不取消定时任务或后台记忆整理。

### 指令

目标群或私聊支持以下会话控制指令，可附带引用或 @ 本机器人。群内无需 @，任意成员均可使用；这些控制指令带额外参数、其他人的 @ 或图片附件时按普通消息处理。

| 指令 | 功能 |
| --- | --- |
| `/help` | 列出指令；不调用模型，不改变会话或普通消息队列 |
| `/new` | 重置当前会话，下条普通消息新建空会话；跳过指令到达前未处理的消息，保留之后的新消息和工作目录 |
| `/compact` | 使用 Pi 压缩当前会话，保持会话关联；没有会话时直接提示 |

这三个指令由不可关闭的 `core` 内置插件注册，在当前轮生成和发送结束后优先执行，处理完成后直接回复确认。控制指令、原始事件和确认回复不进入模型上下文；控制队列只保存去重和执行状态元数据。确认发送失败时重试确认，已持久化的重置或压缩操作不会再次执行。压缩失败后可以再次发送 `/compact`。`/help` 还会列出本实例启用的插件指令；这些插件指令及其实际回复作为聊天记录保存，由插件执行，不再额外触发模型重复回答。

### 失败与中断

1. 模型调用前持久化“已开始”标记，每批最多执行一次。失败或超时后记录终态、推进处理位置，不自动重跑同一批。
2. 每个普通发送分段在准备或发送前记录尝试标记。收到匹配 `echo` 的 `status=ok`、`retcode=0` 才确认成功；准备失败、明确拒绝或结果未确认都结束该项，继续后续项，不补发。
3. Agent 后续失败不撤销已经受理或发送的回复。重启后，已开始批次记为中断，剩余普通回复不续发；未开始的新消息继续处理。
4. 自动模型重试关闭，上下文溢出后的自动重跑被阻止。正常达到阈值的预先压缩和手动压缩保留；控制指令确认使用独立重试队列。
5. Web 安全重启等待当前轮自然结束。Agent 子进程超时或被取消时可单独终止，父 Worker 继续做发送和存储收尾。

QQ 发送与 SQLite 不能原子提交。发送成功但回执丢失、记录尝试后进程退出，都可能导致未确认或丢失的消息；本项目接受这种结果，不自动补发。Console 以内部投递 ID 去重，只有收到 NapCat 成功回执才确认发送成功；单条发送超时不会关闭共享连接。这个策略不保证送达，其他工具也不具备恰好一次执行保证。NapCat 断线期间未收到的事件不由本地恢复。

## 会话与上下文

每轮启动一个运行 Pi SDK 的 Agent 子进程，通过 Node IPC 调用父 Worker 的回复队列。子进程结束后退出，下一轮打开同一个 Pi 会话；会话文件保存在实例数据卷的 `/data/pi/sessions/`。

用户输入是 JSON 对象：`messages` 数组在前，`replyTargetMessageIds` 在后。消息包含 `messageId`、`senderId`、`senderName`、`time`、`text`、`replyTo`，有图时附加图片及本地路径。目标 ID 列表指定本轮应答的消息，其余消息仅作相关背景，不单独回复；纯背景追加时目标列表为空。多个目标来自不同发言者时，可以分别回复。

新进入模型上下文的图片统一限制为长边不超过 1600 像素、单张 Base64 小于 512 KiB（解码后约 384 KiB）。符合限制的小图原样保留；大图由 Pi 缩放并压缩，JPEG 起始质量为 80，必要时继续降低质量或尺寸。原图缓存保留原始文件，历史会话中已经保存的图片不批量重编码。

字段的固定含义由基础指令说明，用户输入只携带消息和本轮目标；触发概率、忙碌判断等调度信息留在桥接层。普通续聊保留已有输入；仅在图片或共享内容版本更新时，由 Worker 在下一轮边界追加正式的上下文修订。旧目标列表不会因此重新激活。

QQ 合并转发由 Console 使用已有的 NapCat 连接读取，正文按 `contents` 中的转发树保存；支持直接内嵌和通过资源 ID 读取的多层记录。外层仍是一条真实消息，内部保留原发言者、原时间及消息段，缺失资料不补造。网页可以逐层展开；模型只使用外层真实消息 ID 回复，不把内部节点当作新到的消息。

转发解析最多 8 层、累计 400 条内部消息、256 KiB 规范化内容，单次总预算 15 秒，每个 NapCat 连接最多 2 个读取请求并发；超限或部分失败时保留已取得的内容并标记缺失原因。当前批次需要该转发时，在提交模型前等待解析终态；迟到更新在后续轮次修订原消息，不自行触发回复。

转发里的普通图片及时进入现有缓存与压缩链路，每条外层消息合计沿用 64 张图片上限，原始鉴权地址不进入模型上下文。语音、视频和文件先保存元数据；内部分享不自动下载或回发媒体，内部指令、艾特及请求只作为引用内容。解析结果和内容更新持久化，重启或重连后按版本恢复。

统一聊天记录区分内部消息身份、真实 QQ 消息 ID 和内容版本，包含用户消息、实际机器人回复、定时回复及插件回复。`replyTo` 来自实际入站引用或经过校验的出站引用参数；系统不会根据“这个视频”等文字补造引用。普通模型回复通过工具调用与发送回执建立对应关系，不再重复追加整段正文；定时图片保留真实资产。

上下文输入采用持久批次提交：先保存待提供版本，Pi 会话文件确认持久化后再提交。进程在确认前退出时按批次核对已写入内容，不重跑旧模型轮次或重发 QQ。未选入本批的记录继续待处理。已压缩的旧消息按真实引用或历史读取恢复最新资料，不自动重写既有摘要。提交元数据不发送给模型。

| 上下文参数 | 默认值 |
| --- | ---: |
| 窗口 | 200,000 Token |
| 自动压缩阈值 | 160,000 Token |
| 预留空间 | 40,000 Token |
| 最大输出 | 8,192 Token |
| 压缩保留的近期内容 | 约 20,000 Token，受阈值约束 |

窗口减去阈值对应 Pi 的 `reserveTokens`，且必须不小于最大输出预算。达到阈值时整理较早历史，保留近期内容；原始 QQ 记录独立保存在 SQLite。窗口配置不会提高供应商的实际容量，`BATCH_SIZE` 也不代表上下文长度。

压缩使用适合聊天和任务混合场景的英文摘要提示，正文可以保留原语言。摘要分别保留近期话题、人物与指代、事实更正、明确未完成的工作及有用产物，不把旧回复目标或未触发的背景问题当成待办。手动和自动压缩复用 Pi 的切点与近期历史保留；摘要失败时不提交、不回退旧模板或重跑聊天。

### 长期记忆

受管实例在配置页启用长期记忆，所有设置保存在控制台数据库。已有实例升级后默认保持关闭，新建实例默认开启；首次启用只整理之后的新消息。旧聊天可以通过实例的「记忆」页选择时间范围异步回填。`/new` 和 `/compact` 不删除记忆，也不跨实例共享。

记忆整理是独立的后台 Agent，拥有自己的英文系统提示、上下文和专用工具，不使用主会话人格或 Pi 会话。每日定时（默认 `Asia/Shanghai` 的 `04:00`）和主会话成功压缩后是两个可独立启用的自动触发器。相同范围合并，无新增材料时不调用模型；每个实例同时只运行一个整理作业。它不占用聊天忙碌状态，不抑制概率回复，不触发被 @ 时的忙碌提示。整理失败不会导致聊天重发；重启后从未提交批次恢复。

主会话只提供 `search_memory`、`search_chat_history` 两个只读工具。用户在聊天中表达记住、更正或忘记的需求，本身作为原始消息保存，到下一次整理时处理，不会立即额外调用模型。当前明确陈述优先于旧记忆，机器人不会提前声称长期记忆已经修改成功。整理器使用 `read_chat_history`、`search_memory`、`stage_memory_changes`，无发送、网络搜索、shell 或定时任务管理工具。变更经来源、人物、版本与排除规则校验后发布，并原子推进进度。

整理工具通过整数 `sourceSeq` 引用本批原文，由后端解析为真实来源 ID，引文仍须逐字匹配。暂存前先完整验证且不写入记忆；错误反馈候选与来源位置，允许同一轮最多三次提交完整修正版。验证成功后正常结束工具轮，不再额外请求模型生成收尾文字；最终发布仍重新校验。整理记录中的失败作业可以「从已保存进度继续」，保留此前已完成的批次与原始回填范围。

人物以用户 ID 区分，自述与转述分开；临时状态、相对日期和事件保存时间依据。原文、记忆来源、修订、整理进度和索引位于实例原数据卷。控制台的编辑、停用、回填和取消均显示异步操作状态，Worker 离线时保持待处理。记忆条目来源、独立的整理工具记录及可见思考在「记忆」页展示，变更经 SSE 更新，不进入主聊天消息流。

相关记忆每轮少量召回，默认最多 8 条、约 3K Tokens，空间不足时先缩减召回。通过 Pi 的请求级上下文变换临时注入当前输入末尾、目标 ID 列表之前，不把相同材料每轮永久追加到会话。中文关键词检索默认可用；可选 OpenAI-compatible embedding 服务使用独立的地址、模型和加密凭据，遵循实例代理。向量随实例存储，服务失败回退关键词，模型变更隔离索引。定时任务默认不读取长期记忆。

停用会阻止后续召回和自动重新学习，但不删除原始聊天或已经存在的 Pi 上下文，不能视为彻底删除所有副本。控制台明确恢复或新的有效记忆请求才能恢复停用项。关闭长期记忆保留数据，聊天摘要适配仍生效。

高级设置可以修改整理模型（留空复用对话配置）、召回预算、压缩近期保留量和摘要输出上限。后台整理与主会话共享宿主机及服务商配额，进程和业务状态隔离不代表资源完全独立；整理使用单并发、有限批次和可取消请求。

Web 会话页展示 QQ 来信、已受理回复、工具调用和图片／语音附件，生成与压缩时显示实际执行状态，失败可查看原因。服务商返回的可见思考内容按轮次合并、默认折叠；生成时持续更新，结束或失败后保留。未返回可见思考内容的请求不生成思考记录，签名与加密字段不进入展示数据。

会话事件先在 Worker 本地持久化，通常合并 100 ms 后独立上传；5 秒心跳只同步运行状态。页面首次获取快照后，通过当前实例的 SSE 接收事件和 Token／上下文增量，不因心跳或其他实例变化重新拉取会话。断线后按 `Last-Event-ID` 从已提交游标补发，重复事件去重；新会话、消息迁移或无效游标使用最新快照恢复。上传失败保留本地记录并退避重试，日志只记录传输元数据。

累计 Token 包含每次请求的输入与输出，缓存读取包含在输入内，缓存命中率为缓存读取 / 输入；未知字段显示 `—`。当前上下文占用与累计用量分开，以 Pi 当前上下文统计为准，估算值明确标记。

## 定时任务

在绑定的 QQ 群聊或私聊中直接描述需求，例如“每天北京时间八点，查指定来源的黄金现货价格，注明数据时间和来源，再与上次有效记录比较”。模型会在时间、数据口径等重要信息明确后调用工具保存任务，并回复任务 ID 和执行计划。也可以在实例的“定时任务”页创建、编辑、暂停、恢复或删除任务，查看运行历史。

任务固定发送到当前实例绑定的会话。在“实例配置 → 高级设置 → 工具权限”中，“仅定时任务创建者可编辑”默认开启：模型工具只允许创建者修改、暂停、恢复或删除自己的任务，其他人查询时只返回任务基本信息；网页创建的任务只能从控制台管理。关闭后，当前会话中的请求者可以查看完整任务定义并编辑全部任务，包括网页创建的任务。工具说明和后端权限校验随实例开关切换，创建人仍保留记录。控制台管理员始终可管理全部任务。

工具的来源必须是本轮应答的真实来信，历史聊天和网页中的指令不能作为任务管理来源；关闭创建者限制仍保留来源、实例范围、版本冲突和脚本权限校验。`/new` 保留任务、业务状态和运行历史。

| 执行方式 | 到点后的行为 |
| --- | --- |
| 脚本 | Worker 执行数据库中保存的 Python 或 Node.js 源码，由脚本 SDK 提交消息；需要开启实例的命令执行权限 |
| 自然语言 | 使用实例当前的模型、人格和可用工具，每次创建独立的 Pi 短会话完成任务；不会续用主聊天或上次任务的完整模型会话 |

支持带明确时区偏移的一次性时间和五段分钟级 Cron，默认时区为 `Asia/Shanghai`。例如 `0 8 * * *` 表示当地每天 08:00，`0 8 * * 1-5` 表示周一至周五 08:00；星期规则不包含节假日调休。“检查计划时间”只校验配置并列出后续时间，不执行脚本、调用模型或发送消息。“立即运行”是正式执行，会发送结果；暂停的任务须先恢复，实例须处于启动状态。

任务定义、源码和历史版本加密保存在 Console 数据库，Worker 在自己的数据卷保存任务快照、执行和发送状态。网页显示已保存版本和 Worker 已应用版本；修改任务不需要重建容器。每次开始执行前，Worker 重新请求 Console 核验启用状态、版本和脚本权限；Console 不可达时不开始新的任务。

### 任务上下文

默认只传任务要求与计划／实际执行时间。创建任务时应保存完整的数据口径、输出要求和必要背景，不依赖后续重读创建任务时的整段聊天。以下两个上下文来源可以组合开启：

| 选项 | 内容与规则 |
| --- | --- |
| 任务状态 | 当前任务专属的版本化 JSON，初始为 `{}`，上限 16 KiB；模型调用 `save_task_state` 或脚本调用同名 SDK 接口显式保存 |
| 指定范围聊天 | 从本实例原始消息及可选的已确认普通回复查询“计划执行日 00:00 至计划时间”“前一自然日”或“计划时间前若干小时”；包含未触发回复的来信，可跨 `/new` |

`save_task_state` 成功后立即提交，并返回新版本；后续模型报错或发送失败不回滚已保存的数据。保存的是已取得的业务检查点，例如价格、报价时间和来源，不代表消息已送达。未取得有效新数据时应保留旧状态；比较时应核对记录日期，不能把前天的有效记录称为昨日数据。修改时间和名称保留状态；业务口径变化时，可在网页显式清空状态。

聊天窗口以计划时间为锚点，排队延迟不改变范围。聊天材料保留发言人、时间和引用关系，排除控制指令、忙碌提示、思考、工具结果及本任务此前的播报；开启机器人回复时包含其他任务已确认发送的发言。历史内容只作为背景，本轮仍只执行保存的任务要求。

范围读取受到条数和输入预算限制；预算采用保守估算，可能比服务商实际 Token 数更大。超出时传入实际覆盖数量和 `truncated` 标记，模型必须说明只总结了覆盖部分。首版不自动分块调用模型进行全天完整总结。任务的内部思考和工具过程留在任务运行详情；已确认发送的实际发言可提供给后续普通聊天，供追问衔接。

### 脚本 SDK

Worker 将源码和辅助模块写入独立的 `workspace/scheduled-runs/RUN_ID/`，以该目录为当前目录执行。源码版本在本轮固定，标准输出和错误输出只记入任务日志；发送必须使用 SDK。Python 示例：

```python
from nekodock_tasks import send_message

send_message({
    "messages": [{"type": "text", "text": "早安，记得按时吃早餐。"}]
})
```

Node.js 使用当前运行目录中的模块：

```javascript
import { sendMessage } from './nekodock_tasks.mjs';

sendMessage({ messages: [{ type: 'text', text: '早安，记得按时吃早餐。' }] });
```

| Python | Node.js | 功能 |
| --- | --- | --- |
| `send_message(request)` | `sendMessage(request)` | 使用与模型 `send_message` 相同的消息结构，受理后返回 `accepted`，不代表送达 |
| `read_task_state()` | `readTaskState()` | 读取本轮状态快照及版本，需要开启任务状态 |
| `save_task_state(data, expected_version)` | `saveTaskState(data, expectedVersion)` | 检查版本并立即保存当前任务的 JSON 状态，需要开启任务状态 |

本轮任务输入位于 `task_context.json`，包含上下文和执行时间。生成图片后发送工作目录内文件的绝对路径，例如 Python 的 `str(Path('chart.png').resolve())`；脚本运行目录与整个实例工作目录不同，直接传 `chart.png` 不代表同一路径。模型、搜索、NapCat 和管理凭据不作为脚本环境变量传递。脚本以 Worker 用户权限运行，与已开启的 Bash 使用相同容器权限，不是独立沙箱。

### 调度、失败与恢复

每个实例的聊天和任务串行执行，控制指令和已触发的聊天优先。定时任务不抽取群聊发言概率；忙碌时等待，开始后同样进入现有忙碌策略。默认允许延迟 600 秒；恢复后最多选择最新一次周期执行，超时记录为错过，不集中补发积压。脚本默认超时 120 秒，自然语言默认 600 秒，均可在任务执行选项中调整。

每个调度点只生成一份执行记录，开始前先持久化领取状态。重启后已经开始的执行记为中断，不自动重跑；发送前保存尝试标记，失败或结果未确认不补发。任务执行结果与消息送达结果分开，例如模型后续失败但已发出一条消息时，显示“执行失败／已确认发送 1 条”。默认失败只留在网页和日志，任务可单独启用失败通知。

停止、重启和实例配置更新会停止领取新任务，等待当前执行与已受理发送收尾。暂停或删除任务停止后续领取，正在执行的版本仍完成收尾。Web 的任务列表、运行详情及会话中的任务事件使用现有 SSE 更新，断线重连后重新获取状态和缺失会话事件。

## 插件

全局「插件」页展示已安装插件和版本；实例「插件」页负责启用和配置。插件代码随镜像发布，开关和参数保存在 Console 数据库，调整插件设置不要求重建 Worker。`core` 始终启用，其他插件按实例独立启用，默认关闭。

实例设置中，独立能力以同级的完整行展示，下载限制、媒体缓存、处理和访问参数分别分组。卡片内容等从属选项在对应能力下缩进显示；关闭能力时保留其选项值，便于预先配置。

每个插件独立放在 `src/plugins/<插件 ID>/`，以 `nekodock.plugin.json` 声明身份、入口和能力；构建时自动发现并校验，未包含声明文件的目录会被忽略。新增插件后重新构建镜像发布，开发约定见 [插件作业与媒体](docs/development.md#插件作业与媒体)。

### 骰子

在实例「插件」页启用「骰子」后，群聊或私聊均可使用 `/dice`，无需 @ 机器人。插件只提供实例开关，不需要模型、网络或媒体配置；启用后 `/help` 自动列出该指令。

| 输入 | 行为 |
| --- | --- |
| `/dice` | 在闭区间 `[1, 100]` 内随机取一个整数 |
| `/dice 1 6` 或 `/dice 6 1` | 在闭区间 `[1, 6]` 内随机取一个整数，端点顺序不限 |
| `/dice -5 5` | 支持负数和零，范围为 `[-5, 5]` |
| `/dice 8 8` | 两端相同时返回 `8` |

自定义范围必须提供两个十进制整数，以半角空格分隔，允许连续多个空格；制表符、换行、逗号和全角空格不能用作分隔符。两个端点均须在安全整数范围 `-9007199254740991` 至 `9007199254740991` 内。参数缺失、过多、非整数或超出范围时统一返回固定的使用提示。

Console 本地计算并持久化结果，重复投递或重启不会对同一条真实消息重新掷骰。原始指令（包括无效参数）和确认发送成功的插件回复都进入聊天记录，在下一次正常主模型调用时作为上下文带入，不额外唤醒主模型或 Jev。模型忙碌时保存指令和结果，待当前轮结束且实例空闲后发送，并引用原始指令；不会再发送忙碌提示。最近处理记录展示指令参数、范围、点数或参数提示，以及来源消息、时间和投递状态。

### 转发图片检查

群聊实例可独立启用「转发图片检查」，无须将普通回复策略切换为 Jev。插件递归统计合并转发中的图片总数，达到「最少图片数」时检查，默认至少 1 张；图片形式的表情包也计入，普通单条图片消息不触发。旧版占比设置升级后使用 1 张门槛，其余插件设置保留。每次最多随机抽样 4 张，可设为 1～16 张；抽样覆盖所有成功解析的图片，包括普通聊天缓存前 64 张以外的图片，恢复任务沿用固定样本。

在插件设置中填写独立的 Jev Base URL、Model、API Key，可配置判定阈值（默认 80%）、单张图片请求超时（默认 60 秒）、补充判断说明与提醒文案。每张图片单独请求，所有检查任务合计最多同时发送两个 Jev 请求；单张超时从实际开始请求时计时，任务另有总体截止时间。请求使用原生 `/systemone` 图片资产协议及 `TypeSafe-Danger-Zone-Images: true` 请求头，采用实例网络代理；端点必须支持 Jev 图片输入。密钥加密保存，公开接口不返回密钥。

默认检查明确色情、露骨性内容，以及明显性暗示、色情化姿势或挑逗性暴露等不适合公开场合查看的内容；真人和绘画／动漫适用相同标准。普通肖像、日常穿着、非性化泳装和非色情艺术不因人物性别、体型或单纯露肤而判为 NSFW。可用「补充判断说明」调整边界；分值不是经过校准的概率。

选中图片沿用正常会话的压缩逻辑，将 Base64 大小限制在 512 KiB 内，并适配 Jev 的静态 PNG/JPEG、280～1568 像素边长要求：保持比例、必要时补边、应用 EXIF 方向，动画只检查首帧。后台队列每实例最多一个、全局最多两个任务，短期图片消费租约避免 Worker 收图后释放缓存影响检查。某张图片超时、读取失败或返回无效结果时保留其他图片的有效分值；任意有效分值命中仍可提醒。全部失败显示「未完成判断」，部分失败显示覆盖情况和逐图原因，均不当作整条转发安全。

相同图片的原图、压缩结果与成功判定按实例复用；模型服务、凭据、补充说明或内置判断标准变化后，旧判定不再复用，失败结果不缓存。不同 QQ 消息仍保留独立聊天记录、来源引用和检查记录。转发结构因深度、条数、大小或超时而不完整时跳过判断；检查错误只在插件记录及日志展示。

任意抽样图片达到判定阈值后，Console 直接发送一条文字提醒并引用外层真实转发消息，不等待主会话空闲，也不额外唤醒主模型。提醒收到发送成功 ACK 后作为插件聊天回复进入上下文和通常的记忆来源；检查过程、采样信息与分值仅保留在插件记录。同一条 QQ 消息重复投递不会重新检查或重复提醒；内容相同的新消息可复用缓存，并按该消息的结果与来源引用处理。关闭插件、修改其配置、停止实例或原消息撤回时取消尚未发送的提醒，发送结果未知时不盲目重发。最近处理记录区分结构完整性、原始图片数量、抽样及成功检查数量、逐图分值和失败原因、请求与缓存复用数量、判定和投递结果。

### 哔哩哔哩

哔哩哔哩增强支持视频、动态／Opus 图文和直播间：识别 QQ JSON 卡片、分享文案、BV／av 视频链接、`t.bilibili.com`、`bilibili.com/opus`、`live.bilibili.com` 和 `b23.tv` 短链。短链在跳转后判断资源类型。同一条消息中的重复资源只处理一次，不要求分享消息触发模型回复。解析资料关联原分享；原始消息保留。

实例插件设置按视频、动态、直播和通用分组。上下文增强与自动展示独立控制：

| 设置 | 默认值与含义 |
| --- | --- |
| 视频上下文增强、尝试获取字幕 | 启用插件后默认开启；字幕可能不存在或需要登录 |
| 视频自动展示 | 默认关闭；可选排版图片，展示标题、作者、发布时间、封面、时长、分 P 和简介 |
| 自动发送视频 | 默认关闭；视频上限为 300 秒、50 MiB、720p |
| 动态上下文增强 | 默认开启；补充作者、正文、话题、原图和一层转发原文 |
| 动态自动展示 | 默认关闭；可选原始图文或排版图片 |
| 直播上下文增强 | 默认开启；补充主播、标题、分区、状态及本次观察时间 |
| 直播自动展示 | 默认关闭；可选文字与独立预览图，或排版预览卡 |
| 通用限制 | 下载总超时 120 秒，本轮最多等待解析 2 秒；媒体缓存每实例保留 24 小时、最多 1024 MiB |
| Cookie | 可选，加密保存；填写浏览器 Cookie 请求头形式，留空保留，清除须显式操作 |

“原始图文”将文字与原图分别发送，动态没有配图时只发文字；直播在播时优先使用有效的平台预览，缺失时使用明确标注的封面。“排版图片”将同一份结构化资料绘制为图片。图片获取或排版失败时，已经取得的文字资料仍保留。动态内引用视频不自动触发视频下载。

视频自动展示与视频上下文增强、自动发送视频分别配置。仅开启排版图片也会解析分享资料；超过下载时长上限的视频仍可展示卡片。视频卡片为 1080 像素宽的单张图片，标题最多 4 行、简介最多 6 行，超出省略；封面保留比例，竖图限制展示高度。封面缺失或获取失败时生成文字卡片，排版失败时降级为文字资料。卡片与视频文件分别处理、分别确认发送，各自就绪后投递，不保证两者的先后顺序，任一处理失败不阻塞另一项。

视频、动态与直播卡片使用一致的作者信息头部：圆形头像、作者名称和辅助信息，长名称自动省略。视频与动态显示发布时间，直播显示房间号。视频卡片准备时补取 UP 主头像，资料或头像不可用时保留已取得的作者名称并继续生成卡片；头像仅用于展示，不额外加入模型视觉输入。

`/bili info <链接>` 查询视频、动态或直播资料，也可引用此前分享代替链接；显式查询只返回文字资料，不叠加一轮自动展示。`/bili download <链接>` 下载视频，动态和直播不执行下载。命令和实际回复进入统一聊天上下文，不触发重复的主模型回答。

解析资料直接补充原分享，迟到结果在下一轮边界修订已提交上下文；资料补齐本身不重新触发回复。支持视觉输入时，可按图片预算提供缓存的动态原图和直播预览；生成的排版图片作为发送事实保存，不重复作为视觉输入。用户原始图片和插件补充图片分别保存来源，避免异步更新互相覆盖。

视频封面用于卡片展示，封面和排版卡片均不额外加入模型视觉输入。关闭视频上下文增强时，自动展示不会向原分享追加视频资料；确认发送成功的卡片仍按实际消息保存。

直播资料保存分享被解析时的观察快照，不持续轮询或改写旧分享。直播中、未开播和轮播分别记录；平台关键帧是最近生成的预览，不保证对应此刻。资料获取时间、图片下载时间和图片文件更新时间分别保存，不作为画面精确拍摄时间。

文字回复可引用来源消息，图片和视频作为独立消息发送，来源关联保存在插件记录中。多条展示产物按顺序投递并分别确认；某项失败或未确认时停止后续发送，已确认产物不重发，未知结果不自动换发送 ID 重试。自动展示等待 Worker 发送队列，超过作业期限取消。插件禁用、实例停止或来源会话被 `/new` 切换后，尚未发送的旧任务不再回发。

哔哩哔哩视频由共享运行器中的固定版本 yt-dlp、ffmpeg 和 ffprobe 解析、下载及验证，优先使用兼容 MP4 的 H.264／AAC；排版图片由运行器中的绘图脚本和中文字体生成。平台请求遵循实例代理，代理失败不静默直连。HTTP 412、权限不足、缺少字幕和图片不可用分别保留状态；获取失败时不编造内容。本期不自动转录音频、识别视频画面或录制直播。

### 小黑盒游戏与帖子

在实例「插件」中启用「小黑盒增强」，可自动识别分享文案或 QQ 卡片中的游戏及帖子链接。支持小黑盒游戏分享入口和 PC、主机、手机游戏页面；分享 ID 可以是数字或不透明字符串，游戏身份同时保留游戏类型与具体平台。

帖子支持分享入口和 `/app/bbs/link/…` 页面，解析实际帖子 ID、作者、发布时间、正文及配图，同一消息内同帖的不同分享入口在解析后去重。帖子上下文增强与自动发送帖子卡片分别控制，默认均开启，不受游戏行为开关影响。正文与配图按原文顺序排版，保留原文链接和页码；不包含评论区。默认最多处理 12 张配图、24,000 字符正文和 32 MiB 图片数据，输出最多 4 页、每页宽 1080 像素；超长图片按比例分段。内容、图片或页数超过上限时明确提示查看原帖，缺图和不支持的内容不会静默当作完整帖子。

帖子图片下载和排版遵循实例代理、单图大小及超时设置。排版失败时保留文字资料与可用原图；解析失败时保留原始分享并记录失败。已发送的卡片作为展示附件记录，不重复作为模型视觉输入。

「游戏上下文增强」与「自动发送游戏卡片」分别控制模型资料和 QQ 图片展示。资料包含实际取得的中英文名称、当前平台、评分、类型、发行资料、简短介绍和价格；缺失字段不补造。卡片使用同一份资料和已下载封面绘制，发送后作为图片附件记录，不重复作为模型视觉输入。图片准备或排版失败时，已经取得的文字资料仍保留。

启用插件后，默认开启上下文增强、自动卡片和卡片价格展示，均可独立关闭。默认单图上限 10 MiB、处理超时 60 秒、本轮最多等待资料 3 秒；媒体缓存保留 24 小时，容量上限 512 MiB。

平台商店价格与小黑盒商城优惠分别展示。商城券后价保留领券、资格等适用条件；记录史低标注为「小黑盒记录史低（该平台）」，不表示全部商店或全部地区的最低价格。不同平台的价格和评分不合并；地区、币种未知时不推测。资料和价格保留获取时间，旧分享不会持续刷新。

详情请求使用小黑盒网页的请求签名，不需要预先填写登录 Cookie。网站接口发生变化、限流或要求验证时，任务在有限重试后保留失败状态；不会用未经确认的其他平台游戏替代原分享。图片大小、作业超时及缓存限制均由实例插件设置控制。

### 抖音视频

在实例「插件」中启用「抖音增强」，可从完整分享文案或 QQ 卡片中识别 `v.douyin.com` 短链、规范视频链接和带作品 ID 的分享页面。插件建立平台正常签发的匿名访客会话，使用移动端分享页取得作品资料；匿名访客 Cookie 不等于真人账号登录凭据，无需预先填写账号 Cookie。短链和媒体跳转逐跳校验，HTTP 200 空页面不视为解析成功。

「视频上下文增强」「视频自动展示」与「自动发送视频」分别配置。开启增强时，将实际取得的发布文案、作者、发布时间、时长、规范链接及字幕状态补入原分享消息。视频没有取得字幕时明确显示状态，不把发布文案当作对白，也不表示模型已经看过视频画面。图集和直播不冒充普通视频处理。

启用插件后，默认开启增强和自动发送视频。默认时长上限 300 秒、大小上限 50 MiB、画面短边上限 720 像素，竖屏视频按短边选择清晰度；单次处理超时 120 秒，本轮最多等待资料 3 秒；媒体缓存保留 24 小时，容量上限 1024 MiB。

「视频自动展示」默认关闭，可选排版图片。仅开启排版图片也会解析分享，视频超过下载限制时仍可生成卡片。卡片使用与哔哩哔哩一致的作者栏，展示圆形头像、昵称、发布时间、发布文案、完整比例的封面、时长及原视频链接。相同的标题与描述只显示一次，文案最多 8 行、超出省略；单张图片宽 1080 像素，竖屏封面限制展示高度。资料解析使用现有 HTTP 客户端，排版使用 Pillow 和字体，不启动浏览器。头像来自同一份作品资料，无需额外查询作者。

头像或封面获取失败时继续使用可用资料生成卡片；整体排版失败时降级为有长度限制的文字资料。卡片准备与视频下载分别处理、分别确认发送，各自就绪后投递，不保证两者先后顺序。头像、封面与排版卡片不额外进入模型视觉输入；关闭上下文增强时不向原分享补充作品资料，确认发送成功的卡片仍按实际消息保存。

符合时长、大小和清晰度限制的视频由运行器及时下载，经文件格式、真实时长和尺寸校验后保存为 Console 媒体资产，再以原生视频消息发送。上游临时播放地址、匿名 Cookie 和签名参数不进入主模型上下文或公开日志，NapCat 只读取我们的受管资产。视频过长、时长无法确认或下载失败时保留已经取得的上下文资料。

匿名身份按实例和网络配置隔离；身份失效时最多刷新一次，网络错误与下载重试均受总时间和次数限制。该插件沿用实例代理、媒体容量和保留期限设置；未知投递结果不自动重发。插件执行不占用主模型会话的忙碌状态，实际视频回发仍由 Worker 发送队列调度。

### 媒体回源与处理记录

启用视频回发前，在对应「NapCat 连接」中配置「媒体回源地址」，例如同一 Docker 网络中的 `http://console:4180`。此地址必须从 NapCat 所在网络可达。保存后使用「检查回源」，由 NapCat 下载一个测试资源验证路径，不发送 QQ 消息。实际视频通过限时签名 URL 获取，支持 HEAD／Range；图片经过校验后使用现有图片快照能力发送，不需要共享 Console 的本地路径，平台 Cookie 不会交给 NapCat。

插件作业、媒体和发送结果均按实例隔离。重启可恢复尚未完成的解析和结果同步；处理记录分别展示资料解析、图片获取与展示准备、实际投递状态，并通过 SSE 更新。会话页可查看视频、动态、直播和游戏资料，以及已发送的媒体附件；缓存过期时显示不可用状态。当前只加载随项目发布的可信插件，不提供任意第三方代码在线安装。

## 搜索、图片与语音

### 网络搜索

同时只启用一个搜索供应商：`none`、`tavily` 或 `deepseek`。启用后向 Pi 注册 `web_search`、`web_fetch`，通过所选供应商的独立 HTTP API 获取资料。搜索供应商与主模型分别配置。

在实例「网络搜索」中配置所选供应商的 API Key 和 HTTP(S) 基础地址，两家服务分别保留地址和密钥。默认返回 8 条来源，可设置 1–20 条；默认超时 30 秒，最多 300 秒。设置保存在 Console 数据库，通过配置版本下发给 Worker。

| 供应商 | 配置与行为 |
| --- | --- |
| Tavily | 默认地址 `https://api.tavily.com`，追加 `/search` 或 `/extract`；支持 `basic` / `advanced` 深度及 `topic`、`days` 参数 |
| DeepSeek | 默认地址 `https://api.deepseek.com`，追加 `/v1/tools/search` 或 `/v1/tools/fetch`；单独填写搜索 API Key，可使用与 DeepSeek 模型相同的 Key，程序不自动继承模型密钥 |

DeepSeek 搜索词最多 128 个 Unicode 字符，支持在查询中使用 `site:`、`-site:`、引号、`after:YYYY-MM-DD` 和 `before:YYYY-MM-DD`。其工具参数为 `query` 和可选的 `maxResults`，不接受 Tavily 的 `topic`、`days`。返回来源按上游排序，优先使用面向模型的 `summary`，为空时使用短摘要。

`web_fetch` 接受 1–20 个 HTTP(S) URL。DeepSeek 按 URL 去重，以最多 3 个并发请求逐页读取，保留部分成功结果；整批读取共用一次超时预算，包含排队和响应正文。取消时停止后续请求并中止正在执行的读取；密钥无效或余额不足时终止整批。DeepSeek 对每次成功搜索、每个成功读取的页面分别按官方规则计费。

搜索和读取沿用实例网络代理与绕过设置。代理服务在宿主机时，将地址中的主机部分填写为 `host.docker.internal`，端口和路径按代理服务的实际配置填写。工具失败返回可诊断错误，不自动重试；DeepSeek 错误区分密钥、余额、限流、网页不可读取、上游异常和超时。

### 图片

入站普通图片在 Console 收到消息时就异步下载，不等待消息触发回复。Console 按实例保存短期快照，Worker 通过鉴权接口获取后，保存到自己数据卷的工作目录 `.qq-images/`。消息入库确认和图片落盘确认独立，Worker 暂时离线或重启时，Console 仍可在链接有效期内预取；Worker 确认图片已保存后释放中转快照。手动停止的实例不接收新消息。

消息和图片通过稳定附件 ID、消息 ID 及图片序号关联，按图片内容哈希在实例内去重。后续触发回复优先读取本地图片，原始鉴权 URL 不进入新的模型输入、会话展示和日志。支持图片输入的模型通过 Pi 图片内容接收；模型声明不支持图片时不附加图像输入。会话页实时展示附件的保存、可用、失败和过期状态。

图片预取独立于主会话执行，不因预取标记模型忙碌。触发回复的批次对未完成图片设置统一等待上限，图片不可用时保留明确状态，不根据文件名猜测内容，也不因图片稍后保存成功自动重跑回复。图片下载遵循所属实例的网络代理设置。

在实例「高级设置」中配置图片缓存：Worker 默认保留 30 天、最多 2048 MiB；Console 中转默认保留 24 小时、每实例最多 1024 MiB。清理时保护尚未消费和正在使用的图片；无法腾出空间时拒绝新缓存并记录日志。压缩上下文和 `/new` 不会立即删除图片；超过保留期或容量淘汰后，保留附件元数据。旧消息的链接仍有效时可补缓存，已失效且未曾下载的图片不能恢复。

出站图片使用工作目录内的真实文件路径或 HTTP(S) URL。桥接层读取后保存 Base64 快照，通过 OneBot `image` 段发送，NapCat 无需与 Worker 共享文件系统。默认单图上限 10 MiB、下载超时 15 秒，支持 PNG、JPEG、GIF、WebP 格式检查。

入站语音、原生视频、表情包和文件暂只保留元数据；哔哩哔哩和抖音插件可解析视频分享并发送视频。通用模型工具暂不发送任意视频，专门的表情包及文件发送仍列为 TODO。普通图片不等同于专门的表情包能力。任务产物目前不自动清理。

### 原生语音回复

同时只启用一个 TTS 供应商：`none`、`edge-tts` 或 `mimo`。语音回复另有总开关和独立概率；关闭时保留供应商配置，开启时必须选择有效供应商。概率按每条逻辑文字回复抽样，与群聊是否参与回复的概率分开。

| 供应商 | 配置与行为 |
| --- | --- |
| Edge TTS | 无需 API Key；选择音色 ID，可调整语速、音量、音调 |
| 小米 MiMo | 单独的 API Key、服务地址、`mimo-v2.5-tts` 模型、预置音色及可选朗读风格 |

MiMo 预置音色：`mimo_default`、`冰糖`、`茉莉`、`苏打`、`白桦`、`Mia`、`Chloe`、`Milo`、`Dean`。额外朗读风格最多 4000 个 Unicode 码点，只影响语音合成，不进入聊天上下文。例如：

```text
以自然、清晰的普通话朗读，语速适中，句间适当停顿。
```

语音通过 OneBot `record` 段发送，在 QQ 中可直接播放。选中的逻辑文字按 `min(REPLY_MAX_CHARS, TTS_MAX_CHARS)` 分段，音频快照持久化后发送；NapCat 端需要具备 MP3 解码与 QQ 语音转换能力。群聊中的原生艾特保留，不朗读 QQ 号。图片、指令确认和忙碌等待提示不转语音。

合成超时、无效音频或超过大小限制时回退到原文字。普通语音或回退文字的发送仍只尝试一次，失败或回执丢失不补发。选中的云端 TTS 服务会收到待朗读文字，MiMo 还收到朗读风格。

| 类别 | 工具 |

## 日志、监控与统计

Web 左侧“后端日志”与“实例总览”“监控”同级，查看 Console 服务；每个实例的“日志”页只查看该 Worker。日志页面每 2 秒读取 Docker 日志，通过 SSE 更新，支持筛选、搜索、跟随、断线重连。最多显示当前容器最近 500 行，不在数据库中另行归档。

宿主机也可查看：

```bash
docker compose -f compose.console.yaml logs --tail=100 -f console
docker logs --tail=100 -f napcat-managed-INSTANCE_ID
```

`INSTANCE_ID` 为控制台的实例 ID。日志时间固定使用东八区，格式为 `2026-01-01T12:00:00.123+08:00 INFO event field=value`。

| 环节 | 诊断字段 |
| --- | --- |
| 批次与发送 | `through_seq`、`run_ref`、`request_ref`、`delivery_id`、尝试和终态 |
| Pi 执行 | `agent.run.*`、`operation`、`api`、`run_id`、`accepted_requests`、耗时、退出和错误码 |
| 工具与压缩 | 工具开始／结束、`item_ref`、状态、耗时和压缩阶段 |
| NapCat | 建连、断开、重连、`echo`、ACK、retcode 与超时 |
| 搜索与 TTS | 供应商、选中路由、来源数、HTTP 状态、字节数和回退 |

`failed` 表示准备失败或明确拒绝；`unconfirmed` 表示可能已经发出但没有成功回执，两者均不补发。`message_ref`、`sender_ref`、`session_ref` 等为短指纹。日志只保留选定元数据，不展示模型原始错误正文、聊天内容、工具参数和结果、完整 URL、文件内容或凭据；会话页按鉴权展示脱敏后的聊天与工具记录。Agent 原始 stderr 不直接转发。

监控独立展示所有实例的 CPU、内存工作集、网络速率和批次端到端耗时。每 15 秒采样，原始数据保留 7 天，之后按 1 分钟聚合并保留 30 天；缺失数据不补成零。时间控件支持快捷范围、绝对时间、缩放和刷新间隔。

今日统计按东八区自然日；入站按真实消息 ID 去重，回复按成功 NapCat ACK 的普通出站条数统计，排除指令确认和忙碌提示。`/new` 不清零历史统计。

## 数据、备份和更新

控制台目录：

```text
console-data/
  console.sqlite3  # 配置版本、实例、账号、事件和统计
  metrics.sqlite3  # 独立指标库
  master.key       # 配置加密主密钥，必须和配置数据库一起备份
```

每个实例的独立数据卷：

```text
/data/
  bridge.sqlite3      # 目标、消息、处理位置、控制队列、发送尝试和会话事件
  schedules.sqlite3   # 任务快照、调度点、执行、业务状态、发送尝试和待上传事件
  pi/sessions/        # Pi 持久会话
  workspace/          # 脚本、下载、图片缓存和生成产物
  console-media/      # 供鉴权会话页面读取的媒体快照
  managed-config.enc  # 控制台不可用时使用的加密配置缓存
```

SQLite 使用 WAL 和 FULL 同步。在线备份使用 SQLite Backup API；或安全停止对应服务后备份完整目录。不要在 WAL 活跃时只复制单个 `.sqlite3` 文件，也不要只备份数据库却遗漏 `master.key`。单个目标的数据卷只运行一个 Worker。

功能、提示词或镜像依赖更新并验证后，公共镜像只构建一次：

```bash
docker compose -f compose.console.yaml --profile build build worker-image
docker compose -f compose.console.yaml build console
docker compose -f compose.console.yaml build plugin-runner
docker compose -f compose.console.yaml up -d console plugin-runner
```

按顺序执行构建，每条命令只指定一个服务。构建前检查可用内存、Swap 和磁盘；小内存主机应限制编译进程内存，并观察换页压力。`COMPOSE_PARALLEL_LIMIT` 不能保证 Buildx Bake 内部逐个编译服务。

在 Web 先对一个验证实例执行“重启”，确认运行正常后，再逐个重启其他受管实例。控制台等待当前轮生成和发送收尾后重建容器，复用原卷；检查运行状态、NapCat 连接、配置版本及 Pi 会话。不要强杀仍在处理或有待发记录的容器，不要启动复用同一卷的第二个 Worker。

每次更新前记录三个服务的当前镜像 ID，保留一组回滚版本。全部实例更新并验证成功后，清理本项目更早且没有任何容器引用的镜像，以及已被新容器替换、排空并停用的旧容器。保留正常停止的受管实例容器、当前镜像、仍被容器引用的镜像和最近一组已验证的回滚镜像；更新失败时保留回滚资源。删除镜像逐项执行，不使用强制删除。检查构建缓存，在共享 Docker 主机上只清理能确认归属本项目的缓存；清理前后检查磁盘用量和容器状态。不要执行全局 `docker system prune`、`container prune`、`image prune -a` 或卷清理；数据卷、数据库、配置及备份独立保留。

控制台不可用时，Worker 可从加密缓存读取上次配置并继续处理；会话事件先在本地持久化，控制台恢复后按序同步。接管已有实例后，不要启动任何复用原数据卷的旧容器。

npm run build:web
